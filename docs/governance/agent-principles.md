# Agent 协作与知识边界原则

本原则记录用户批准的协作边界。角色授权不等于当前执行环境已实现访问隔离。

## 角色与知识来源

只有用户指定的规格负责人兼里程碑裁判可以只读研究旧项目，提炼协议、兼容性、历史风险与验收标准。

编码负责人、子 Agent、审查及验收 Agent 仅使用 Homevoice 仓库内的项目知识，不直接或间接研究旧仓库。旧项目不作为构建、运行或验收依赖。

正常工具链、公开依赖文档与授权测试设施可用；其他私人项目、旧源码、家庭配置与秘密不属于授权范围。

## 不允许的绕过

- 直接打开、搜索旧代码，或从网络下载旧仓库作为参考。
- 借助另一个 Agent 代查旧源码。
- 通过挂载、符号链接、submodule、外部脚本或完整副本扩大访问。
- 将旧行为默认为新规格正确答案。

## 知识转移

规格负责人提供本仓库内自包含资料：协议结构/时序、兼容性矩阵、安全规则、脱敏样例、失败场景和设计决策。

资料区分源码推断、模拟验证、真实硬件验证，并记录必要的版本与来源。不得只提供指向无权读取资料的链接；不搬运生产秘密或未核验许可证的代码。

执行者发现信息缺口时，提交具体问题、已查本仓库文件、失败证据和受影响验收项。由规格负责人补齐资料，必要时批准规格变更；不得靠猜测或扩大访问解决。

## 自主编码

编码负责人可在批准的范围、资源与工具授权内决定串行、并行、分工与集成；所有子 Agent 继承规则。

最终交付是一个可运行、可验收的版本。未经批准不得改外部契约、安全规则、测试门槛或增加产品范围。

不同工具能否自动派发任务取决于实际 CLI/API 支持，不预设已经具备自动调度。并行实现使用清晰任务边界和独立工作区，不同时修改同一问题。

## 独立验收

实现者自验不替代独立验收。验收角色在独立上下文中依据批准规格检查固定候选版本，报告证据。

裁判最终判定通过、不通过或待验证/阻塞。新增要求必须进入公开规格并说明影响，不能用临时隐藏标准追溯否决交付。

自动代码审查提供线索，不证明里程碑满足需求；真实硬件能力须有真实结果。

## 初始工具分工

以下是初始建议，并非模型能力排名或额外执行授权；经 M0 实测可调整。

| 工具 | 角色 |
|---|---|
| 用户指定的主助手 | 规格、跨仓库研究与裁判 |
| DeepSeek harness | 主力编码、测试与集成负责人 |
| Cursor GitHub 自动审查 | PR 缺陷线索 |
| Cursor Composer / Grok | 问题复现、定位、修复与回归测试 |
| Kimi Code | 关键安全节点二审与疑难升级 |

同一问题只指定一个修复者。修复者负责的结果仍需复验，不能自行成为唯一裁判。

## 环境和敏感操作

条件允许时，仅向执行 Agent 挂载新仓库，避免继承裁判的旧项目上下文。工作目录设置或提示词不是文件系统隔离。

初始化文件不授权提交/推送、部署、真实硬件控制、OTA 或破坏性迁移。生产密钥不放进交接包；测试凭据独立、受限、可撤销。
