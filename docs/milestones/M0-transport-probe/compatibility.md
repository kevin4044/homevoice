## 后续功能的前置能力调查

| 功能 | M0 仅调查 | 不做 |
|---|---|---|
| 主题 | 目标工具/配置、固件支持与资源限制 | 发布或生成完整主题 |
| 固件 OTA | HTTPS、板型、验签、分区、回滚能力与信息来源 | 更新真实固件或开自动升级 |
| 配对/撤销 | 凭据存储、轮换、恢复出厂影响 | 生产注册系统 |
| HA 房间 | 授权只读接口与实体命名结构 | 真正控制家电 |

## 必须形成决策的风险

| 风险 | 不可接受的结论 | 可交付的处理 |
|---|---|---|
| 固件无 notify | “MQTT 能连接所以通知通过” | 明确需授权升级/改固件，M0 路线阻塞 |
| 共享上行主题 | 用 JSON 设备 ID 当身份 | Broker 可信身份回调，或验证独立主题与 ACL |
| MQTT 不支持 TLS | 直接默认公开明文服务 | 私有隧道/家庭网关或固件改造方案 |
| UDP 无 MAC/AEAD | “加密了所以安全” | 记录注入/首包抢占/重放边界，决定隧道或固件安全改造 |
| CTR 双向计数器 | 时间戳非零就宣布无碰撞 | 记录方向/计数器范围，制定可验证补救方案 |
| NAT 地址变化 | 接受任何新源覆盖 peer | 新 HELLO 重建；评估网络稳定性 |
| 固件无设备 MCP | 按虚构工具名实现 | 记录固件改造要求，由裁判决策 |
| 配置下发需旧共享令牌 | 将其搬到新生产系统 | 仅授权隔离迁移，设计受控注册渠道 |

M0 可以证明兼容路线并提出后续安全方案，但未决关键安全部署方案不能被裁判当作已解决。公网发布是另一个授权和验收门槛。

## 验证记录格式

每项填写：`状态（通过/失败/阻塞/未执行）`、`环境与版本`、`证据编号`、`操作者与授权范围`、`限制`、`后续决策`。

不要在本表保存真实 MAC、家庭 IP、用户名、密码或证书私钥；使用别名，敏感配置在新仓库忽略的 `local/` 中且不提交。脱敏报告可进入仓库。
