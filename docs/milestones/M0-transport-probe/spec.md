# M0 规格：MQTT + UDP 隔离探针

版本：`M0-v0.1`，待批准。依据用户的最新设备通信路线决定：MQTT 控制与通知、UDP 音频；设备 WebSocket 延后。

## 目标

证明 Go 可以完成目标固件的 MQTT 连接、HELLO、加密 UDP 双向音频、打断/重连、通知及设备 MCP；用最小模型工具循环和远程 MCP 探针验证后续 Agent 所需接口。明确固件和安全限制，再决定 M1 方案。

## 必需能力

| 编号 | 要求 |
|---|---|
| R01 | 可重复的 Go 工具链、依赖锁定、模拟测试与报告，不依赖旧服务 |
| R02 | MQTT 3.1.1 设备连接与身份绑定，凭据缺失/错误拒绝 |
| R03 | 可信连接身份随上行消息传入，发布/订阅权限隔离 |
| R04 | `transport=udp` HELLO，独立密钥、SSRC、协议会话和连接代次 |
| R05 | 按协议完成 UDP 帧长、AES-CTR、方向、序列和来源检查 |
| R06 | Opus/PCM 双向转换，分别记录上下行格式和采样率 |
| R07 | MQTT 与 UDP 播放时序、节奏、尾帧、打断和资源收口 |
| R08 | MQTT 在线与 UDP 会话存活分离；验证 Idle 下通知 |
| R09 | 设备 MCP 初始化、分页、响应关联、取消和实际能力枚举 |
| R10 | 有界模型工具调用，将合成音量工具绑定当前设备会话 |
| R11 | 独立的远程 MCP 查询探针，不操作真实 HA 写工具 |
| R12 | 隔离环境证据、固件能力和公网安全限制有明确结论 |

## 明确不做

设备 WebSocket、生产注册/管理后台、持久记忆、知识库、Skills 平台、家庭 HA 写操作、生产公网部署、MQTT 协议从零实现、固件编译/发布、自动升级、主题系统及飞书等渠道。

测试用 HTTPS 配置下发只验证 MQTT 凭据和主题能否写入目标固件，不实现正式注册或固件下载。不得凭自报 MAC 发放任意真实设备凭据。

## 最小实现方向

Go 模块化探针，优先复用维护中的 MQTT Broker 库和标准密码库。Broker 必须提供已鉴权发布者与连接代次，不能把普通 MQTT 订阅客户端收到的 payload 当作可信身份。

若成熟库无法满足目标固件，提交具体证据和方案选择，不自行改成 WebSocket 或手写完整 Broker。外部 Broker 仅在能够证明身份来源或独立上行主题受 ACL 保护时采用。

测试凭据预先登记到隔离配置，不采用生产共享密码。随机数使用 `crypto/rand`；密钥不得基于 UUID、设备 MAC 或递增值生成。

## 默认探针限制

| 项目 | 上限/初值 |
|---|---|
| 注册设备 | 2 台；额外身份拒绝 |
| MQTT CONNECT / HELLO 等待 | 各 5 秒；MQTT Idle 本身不强制等待 HELLO |
| MQTT 报文/JSON | 64 KiB；超限关闭或拒绝，记录脱敏原因 |
| UDP 总报文 | 1500 字节，载荷最多 1484 字节 |
| 每设备音频队列 | 64 帧；满时丢帧并计数，不无限分配 |
| 单轮收音 / 上游操作 | 15 秒 / 30 秒 |
| MCP 单请求 / 工具列表 | 5 秒 / 最多 8 页、128 工具 |
| 模型调用循环 | 每轮最多 2 次请求、1 次工具执行 |
| TTS 初始调度候选 | settle 150 ms、预缓冲 5 帧、尾等待 2 额外帧 |
| 下行音频候选 | Opus，单声道，24 kHz、60 ms |
| 测试云调用预算 | 最多 3 轮；每轮 ASR≤1、LLM≤2、TTS≤1 |

这些是探针限制和调优起点，不是已验证固件参数或产品 SLA。若需调整，记录依据，由规格负责人批准；测试仍须证明有界。

## 安全边界

- 仅 loopback 或明确授权的隔离私网地址，拒绝默认 `0.0.0.0` 公网监听。
- 明文 MQTT 只可用于明确批准的隔离实验，不能成为生产默认或认证失败后的自动降级。
- 测试 HTTPS/MQTT TLS 不能跳过证书校验；设备不支持安全连接时记录阻塞和改造选项。
- UDP AES-CTR 不提供真实性；来源锁定、Opus 解码和序列窗口不替代 MAC/AEAD。
- SSRC 明文可见，首次锁定存在抢占风险；双向共享密钥还需评估计数器碰撞。
- M0 不私改线格式加入固件不支持的认证标签；公网发布须有明确补救设计与批准。
- 通知仅测试指定设备的无敏感合成内容；MQTT 发布成功不证明播放完成。

## 通过条件

所有必需离线测试通过；至少一台目标固件真实验证双向语音和 Idle 通知；设备 MCP 与模型/远程 MCP接口获得明确证据；兼容性清单填写，无未决关键路线或身份来源问题。

目标固件缺少必要通知/MCP能力，或公网安全方案尚未确定时，报告阻塞或待决策，不暗中降低要求。M0 通过也不授权公网部署；M1 仍需实施安全闭环。
