# 里程碑交接与验收流程

## 交接包

每阶段启动前，由规格负责人在本仓库准备并获得批准：

```text
docs/milestones/M<N>-<name>/
  spec.md          范围、接口、状态、安全规则与非目标
  tasks.md         实现任务、依赖和修改边界
  acceptance.md    验收场景、实际命令、预期结果与证据
  handoff.md       授权、前置条件、资源限制与升级规则
```

必要的脱敏样例与模拟设施保存为仓库内测试资产。具体文件在阶段规格成熟时创建，不预先提供空模板冒充可执行计划。

## 执行闭环

1. 裁判冻结阶段范围和验收标准，用户确认必要授权。
2. 编码负责人检查环境、资料和前置阶段，自主安排实现。
3. 实现者补测试、实现、自验并集成为一个候选版本。
4. 自动审查与独立验收对照原始规格检查代码及运行结果。
5. 问题由一个指定负责人修复，补回归测试，再对新版本验收。
6. 裁判依据要求、实现、测试与证据判定结果并交接。

## 验收入口

每阶段规格必须定义真实可运行的统一验收入口，覆盖适用的格式、静态检查、单元/集成、安全回归与硬件测试。

本仓库当前没有代码或验收脚本，不能运行或宣称任何 `make verify-*` 命令已存在。实施后才新增并记录实际入口。

模拟 LLM/ASR/TTS 和 HA 用于可复现失败与权限测试；真实硬件验收验证模拟不能证明的固件行为。

## 完成报告

候选交付报告必须包含：

- 规格版本和候选 commit；未获提交授权时使用明确的文件差异快照并说明状态。
- 每个验收条目的结果：通过、失败、未执行或不适用及理由。
- 真实执行命令、环境、结果与脱敏日志。
- 模拟测试和真实设备测试的区别，设备固件版本与能力限制。
- 未解决问题、数据迁移/恢复影响和回退方法。
- 资源、费用和耗时限制是否遵守。

## 阶段判定

**通过：** 必需验收均有证据，没有未解决的阻断安全或正确性问题。

**不通过：** 明确违反已批准规格，返回具体缺陷和复验要求。

**待验证/阻塞：** 缺少真实设备、权限或前置条件；不得将编译或模拟通过冒充最终完成。

规格与关键验收门槛未经批准不可修改。新发现的风险由裁判明确纳入变更，不接受实现者自行删测试或降低标准。

## 失败与升级

阶段交接时约定修复轮次、上游调用预算和整体时间限制。超限或持续失败后提交原因、尝试与证据，不无限重试。

真实设备操作、家庭迁移、公网发布、OTA、破坏性数据库操作和 Git 发布按显式授权执行，自动协作不扩大权限。
